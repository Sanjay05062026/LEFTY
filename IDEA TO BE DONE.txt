6. LLM NOTES (everything we discussed)
--------------------------------------------------------------------------------
  Building a model from scratch: not possible (millions of dollars of
  compute). Realistic: take an open model (Qwen, Gemma, Llama) and
  fine-tune it on Lefty's own data. Pitch it as "self-hosted, fine-tuned
  open model". Never claim "trained from scratch".

  Vision vs text-only:
    Text-only reads only words. Vision models also see images (screenshots,
    photos, scanned PDFs). Vision adds an image encoder: about 0.5-1 GB more
    VRAM and slower. Lefty sends both a text button list and a screenshot;
    the button list alone is often enough for normal apps.

  What fits (4-bit, short context; estimates):
    Model                        VRAM needed   4 GB   6 GB          8 GB
    3-4B vision                  ~3-3.5 GB     yes    yes           yes
    7-8B text only               ~5-5.5 GB     no     just barely   yes
    7-8B vision                  ~6-7 GB       no     spills, slow  yes
    If a model is bigger than VRAM it spills into RAM and gets several
    times slower. Laptop VRAM cannot be upgraded (soldered).

  Speed estimates (to be benchmarked):
    4B vision on RTX 2050 (4 GB):  ~4-8 s per step
    4B vision on RTX 3050 (6 GB):  ~3-5 s per step
    8B text on RTX 3050 (6 GB):    ~3-6 s per step
    Gemini now:                    ~3-5 s per step (measured 4.9 s once)

  Context and tokens:
    Context = everything the model reads at once (instructions, goal, button
    list, history, its answer). Measured in tokens; 1 token ~ 3/4 of a word.
    A real Lefty request measured 1,862 tokens in + 46 out.
    4,000-token context is enough for Lefty and costs ~0.5 GB on an 8B model.
    8,000 ~ 1-1.2 GB, 32,000 ~ 4-5 GB (does not fit the LOQ).
    Long PDFs and big code files go to Gemini (about 1 million tokens).

  Do tokens run out?
    Our own model: never. Free and unlimited; only the per-request context
      limit applies.
    Gemini free tier: per-minute and per-day limits that reset. Images and
      big PDFs use quota fastest. Check limits at aistudio.google.com.
    Long chats: old messages get trimmed; the memory layer keeps what matters.

  LOQ setup (8B text, ~5.7-6.1 GB total, right at the limit):
    setx OLLAMA_FLASH_ATTENTION 1
    setx OLLAMA_KV_CACHE_TYPE q8_0
    (roughly halves context memory; restart Ollama after)
    Candidates: qwen3:8b (turn thinking mode off for speed), llama3.1:8b
    Keep ONE model loaded per machine; swapping costs several seconds.

  Victus vision model: qwen2.5vl:3b (leaves headroom on 4 GB).
  Victus Ollama: installed, no models yet, models stored on D:\OllamaModels.

  Why "30% of Claude" is the wrong target:
    Lefty already uses a frontier brain (Gemini). What makes an assistant
    feel good is also the harness: read the situation, plan, act, check,
    retry, fail out loud, route easy work to fast models and hard work to
    strong ones, stream answers. That is what Phase 0 adds.

8. FINE-TUNING AND GETTING BETTER AFTER EVERY CHAT
--------------------------------------------------------------------------------
  Layer 1 - better after every chat (no training), build first:
    - Solved routes replayed directly with no AI call (~1 s instead of ~5 s)
    - User corrections and preferences remembered
    - Similar past successes added to the prompt as examples
    - Works with any brain, including Gemini. User can view and delete memory.

  Layer 2 - a better model every week (fine-tuning):
    Use Lefty -> collect verified good steps -> fine-tune on Colab/Kaggle ->
    test on the 20-task benchmark -> switch only if better, keep the old
    version for rollback.
    Good example = screen check confirmed it worked and the user did not
    stop or correct it. Thumbs up/down adds signal. Good-vs-bad pairs can
    teach what not to do (preference training, DPO).
    Not after every single chat: risk of learning mistakes, forgetting,
    cost, no safety check.

  Time estimate (part-time):
    Collect 1,000-2,000 examples   3 days (automated) to 2 weeks (normal use)
    Clean data                     1-2 days
    Set up training notebook       ~1 day
    Train                          ~1-3 h (8B text), 2-5 h (4B vision)
    Convert + load into Ollama     a few hours
    Test                           half a day to 1 day
    Second round                   2-3 days
    First good version: ~1.5-3 weeks part-time, ~4-6 days focused.
    Each later version: ~1 day.

  Tips:
    - Fine-tune the 8B TEXT model (training data is text, faster and cheaper).
    - Start logging in Phase 0 so data collects during all of Phases 1-4.
    - Our 4 GB / 6 GB cards can RUN the model but not train it; train on
      free Colab / Kaggle GPUs.

  Pitch: "Lefty gets better the more you use him" - live replay (5 s first
  time, 1 s from memory) and a chart of v1 -> v2 -> v3 success rates.
